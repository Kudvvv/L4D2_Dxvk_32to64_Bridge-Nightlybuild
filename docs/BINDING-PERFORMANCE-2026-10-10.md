# 重复缓冲区绑定的引用开销

本轮以 v1.1.10（`bcacb4727007ad040f0f6447a4e258f0456469de`）为基准，减少 Bridge 重复绑定缓冲区时的引用计数操作。**正确性回归、云端构建和游戏对照已完成；两组配对实测中平均 FPS 略高、1% low 略低，尚未证明稳定的性能提升或回退。** 在阅读这些结果后，维护者于 2026-10-10 授权合入并正式发布。性能观测和限制完整保留，发布决定不代表已经证实 low 帧收益。

## 改动范围

Client 的 `SetStreamSource` 与 `SetIndices` 在实际目标槽位已经持有相同资源时，省去临时智能指针引起的增减引用。四处判断分别覆盖当前设备状态和 StateBlock 捕获状态。判断位于原设备锁内；首次捕获仍独立持有资源，不同资源仍先持有新对象再释放旧对象。

所有 Host 命令、顺序、UID、参数、offset/stride 更新、dirty flags、诊断计数、可选响应等待和 HRESULT 保留。特别是 DrawUP 后，即使 Client 保存的资源指针相同，也仍发送重新绑定命令。没有降低画质、改变默认配置、添加功能或修改 CPU 调度策略。

## 回归与证据边界

测试从应用生产补丁后的源码提取完整 setter、`D3DAutoPtr`、StateBlock `StateTransfer` / `Capture` / `Apply` 和响应宏；原版由精确移除四处判断获得。COM 资源、锁、消息传输与诊断使用功能适配器。比较完整消息及状态轨迹，覆盖资源替换、null、参数变化、独立捕获、外部引用归零、销毁、Host 错误和超时。

本地 MinGW x86/x64 的同步模板及诊断开关组合通过，四个故意破坏行为的变体均被检出。每组 2,067 条消息及语义轨迹一致；2,000 次相同资源绑定的智能指针 retain/release 从 2,000/2,000 次降到 0/0 次。测试不是多线程互斥、实际跨进程 IPC 或完整 COM/Host 销毁协议验证；DrawUP 仅模拟 Host 绑定清空的效果。

候选提交 `af678d1a349d078952b1554aaa2c51bc2bde9678` 已通过 [Actions 38053045069](https://github.com/NPCodex/L4D2_Dxvk_32to64_Bridge-Nightlybuild/actions/runs/38053045069) 的完整 MSVC 编译、两种架构的绑定回归、原有原生回归、ThinFlex 及全量包校验。该运行使用 `validation_only=true`，发布步骤已跳过。本地 Python 回归运行 166 项，其中 18 项按环境跳过，整体通过。

生产补丁只替换 `d3d9_device.cpp` 的原补丁段，分别通过 NVIDIA 基准 `9aa74f8dfad2188efbd0f717c64d9f8fa909787e` 和固定构建源 `5fd30eae2d397f369bdf5660f3ddd0bc0bd1fa58` 的应用检查。未从含旧实验的依赖工作目录重新导出整份补丁。

## 未采用的队列实验

Host 缓存已 acquire 观察的队列发布边界，通过了 18 项正确性检查（含预期失败的负对照）。40 个微基准样本中，Host 方向容量 8 的吞吐配对中位改善约 12.96%，容量 256 仅约 0.22%；实际 Device 队列默认容量为 3072。证据不足以外推游戏收益，本轮没有将此候选并入生产。

## 游戏对照

沿用[上轮测试口径](FLASHLIGHT-PERFORMANCE-2026-10-10.md)：Ryzen 9 9950X3D、RTX 5090 D，4K、MSAA 8、各向异性 16，固定 Tumtara 位置、视角、角色与武器，保持同一份 L4N、配置和匹配 GPLALL 后端。无桥为 x86 GPLALL，Bridge 为 x64 GPLALL，架构差异仍是对照的边界。用户自行关闭全局垂直同步；没有更改该全局设置。

每轮重新启动游戏，按开灯 / 关灯 / 再开灯各采样约 65 秒。采样期间没有本地编译、大文件分析或截图；采样前观察、激活窗口，并用游戏原生命令核对前后镜头和灯状态。没有连续前台日志，不能宣称严格证明整个采样期间始终处于前台。

双 CCD 的临时统一核心范围（游戏和 Host 均为 CPU 0–15）仅用于控制测试变量，不随包启用。上轮约 285 → 351 FPS 的调度差异不能计为本次代码收益。

## 数据检查与恢复

所有表内段的 CSV 哈希、单 PID / 交换链、递增时间戳、前后场景和输入文件哈希通过独立检查，没有 ETW 丢事件提示。均记录 `SyncInterval=0` 和 Independent Flip。B4 关灯段 24,265 行中只有最后一行 `Dropped=1` / `AllowsTearing=0`；其他行及其他段均无丢弃且允许撕裂。保留该原始末行及完整样本，没有删除后只报告更有利的结果。

最初 B1 因用户暂停以关闭垂直同步而中断，B2 因电脑控制中止没有采样；B3 出现 ETW 丢事件且没有生成 CSV，均排除。只清理已确认属于 B1 的残留 PresentMon 会话，10 秒工具探测通过后再开始 B4。系统 CPU 采样权限不足，未取得 WPR 线程执行跟踪，因此没有将瓶颈归因到具体线程或 GPU 等待。
