# PR #6 回绕修复实机测试

修复已知完整布局的数据包在部分游标位置因尾部填充而超容量的问题。
不按 64 MiB 特判：Surface 普通/ATI 上传声明完整线缆长度；共享堆保持相同字段。
完整包序列化器也复用回绕处理。超过队列实际容量（包括 UID 和长度/字段）的包仍拒绝。

Client 在写任何字段前验证完整布局。需要回绕时，先发布一个无应用副作用的填充 Header；Host 单读线程按已发布边界消费填充并确认，然后才允许完整包覆盖起点。
未消费数据、动态 Lock pin、超时/失败后禁止提交的约束不变。无新增 mutex、常驻缓冲区或按包大小阈值；回绕冷路径增加一条 Header。协议版本改为 3，必须使用配套二进制。
这不是无限大小上传/分片功能：无法放入空队列的包仍失败；未声明布局的旧式增量命令仍使用原安全检查。
