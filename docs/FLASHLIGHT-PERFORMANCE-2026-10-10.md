# 手电性能对照与命令热路径优化

2026-10-10 完成本机 v1.1.4、优化候选 v1.1.9 与同版本无桥 GPLALL 的对照。候选在临时统一 CPU 核心范围后，手电降幅约 5.7%–5.8%，无桥约 4.7%，已接近用户接受的正常手电开销。**这不证明代码消除了自然调度下的异常低档，也没有证实平均 FPS、1% low 或 0.1% low 的稳定提升。**

保留的改动是减少可确认的命令热路径冗余，不增加功能，不降低画质，不修改默认配置或 CPU 调度策略。发布版从下述已测生产补丁重建；版本、构建标识及说明发生变化，发布 ZIP 不能称为已经逐字节实测的候选 ZIP。

## 生产改动与验证

- 队列已经有数据时，`peek` / `pull` 直接执行原有 acquire/release 读取与槽位释放，避免没有用途的时钟读取。空队列的等待注册、复查、唤醒和取消协议保留；超时预算从首次发现空队列之后的时钟读取开始。
- Command 的四处进程内保护标志读写改为 relaxed。Client 仍持有原写入锁，Host 仍要求每个通道单写入者；跨进程载荷发布、互斥锁和等待协议不变。
- Host 浮点常量缓存没有建立可重复净收益，已从最终生产补丁移除。忽略目录中的旧实验不参与构建。
- 候选提交 `abe72bf8954cfae0b0ba87631bcfd58ef646bf31` 已通过 [Actions 38046094043](https://github.com/NPCodex/L4D2_Dxvk_32to64_Bridge-Nightlybuild/actions/runs/38046094043) 的完整 MSVC 构建、原生回归、ThinFlex 和全量包校验。Python 回归 166 项，18 项按该运行环境跳过；生产 Command 翻译单元的 x86 Client → x64 Host 回归覆盖 3 种内存序、12 个场景、414,576 次发布。测试不能替代全部生命周期或长期游戏稳定性验证。
- 补丁分别检查 NVIDIA 原始基准 `9aa74f8dfad2188efbd0f717c64d9f8fa909787e` 与固定构建源 `5fd30eae2d397f369bdf5660f3ddd0bc0bd1fa58`。偏色、ThinFlex、GPLALL、默认 x64 Host、L4N 与精简全量包结构保留。

## 测试条件与口径

Ryzen 9 9950X3D、RTX 5090 D、驱动 617.42；L4N、GPLALL 2.6.8，4K、MSAA 8、各向异性 16，固定 Tumtara 位置、视角、角色和手枪。三种模式保留同一份 `dxvk.conf` 和视频配置；无桥使用匹配的 x86 GPLALL，Bridge 使用 x64 GPLALL。两种架构的着色器缓存及编译线程数不同，不能称为完全相同的执行路径。没有清理玩家缓存。

每轮 ON / OFF / ON2 各采集约 65 秒 PresentMon 数据，采样期间不编译或处理大型 CSV。采样前观察并激活游戏窗口，以游戏原生命令核对位置和手电状态，归档后检查 Bridge 焦点日志。无桥没有对应的 Bridge 焦点日志；没有失焦日志也不能证明每一时刻都在前台。两种 Bridge 的场景查询文本一致；14 个渲染/CPU/GPU cvar 未能通过控制台读取，不将配置哈希冒充完整运行时画质证明。

为了控制本机双 CCD 调度差异，表内三种模式均临时限制到 CPU 0–15（96 MiB L3 所在 CCD）。这是诊断条件，不是随包启用的配置。它同时改变缓存共享、跨 CCD 通信、可用核心和竞争，不能只归因于其中一项。采样后的现存线程和进程恢复校验、退出状态及游戏文件恢复记录留在本地。

平均 FPS 采用 `(Present 数量−1)/时间`；1% / 0.1% low 是最慢对应比例的正 Present 间隔均值换算。它们描述提交节奏，不等同于完整显示帧率。每段 0.1% 尾部只有约 20–25 个样本；最高瞬时 FPS 容易受提交批次影响，不作为本轮收益指标。

## 自然调度下的两档帧率

同一个 v1.1.4 游戏进程，未限制 CPU 时 ON / OFF / ON2 约为 284.81 / 334.82 / 285.92 FPS；临时限制到上述 CCD 后，35 秒诊断段变为 351.12 / 376.55 / 351.57 FPS；恢复允许使用全部 CPU 后，另一个 35 秒开灯段仍约 347.18 FPS。

这说明运行状态和调度控制对本机结果的影响远大于候选代码的小变化。恢复允许 CPU 掩码并不恢复调度历史和缓存状态；线程 ideal processor 也只是偏好，不是实际驻留证据。**不能把约 285 → 351 FPS 写成代码优化收益，也不能认定所有玩家的掉帧都来自 CCD。** 本次不发布硬编码绑核、不改 Windows 调度或电源设置。

## 收尾与证据范围

本轮结束后正常退出游戏与 Host，81 个原始非日志文件逐一通过 SHA-256 恢复校验，移除 3 个自建临时配置和 1 个地图链接。最后一次自动恢复曾无法打开 5 个旧线程 ID；退出前的后续快照中这些 ID 已不存在，两个进程与全部已枚举现存线程均恢复原掩码，随后确认原进程退出。保留首次失败记录，不把它改写为首次恢复成功。没有更改全局 VSync、G-SYNC 或玩家长期配置。

原始 CSV、日志、安装备份和线程恢复记录仅保存在本地，未上传。旧版 [固定 L4N 回放报告](PERFORMANCE-2026-10-10.md) 的提升数据属于另一次改动，不能用于宣称本次优化收益。
