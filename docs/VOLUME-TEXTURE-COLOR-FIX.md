# 三维纹理偏色修复

移植来源：[keyou91 的 PR #3](https://github.com/yeyunyyds/L4D2_Dxvk_32to64_Bridge/pull/3)，提交 `fb1507d`。保留该作者的修复；它不属于本仓库原有的 Codex 生成来源声明。

`bridge/src/client/d3d9_volume.cpp` 原先把每行块数和每层块行数返回为 `D3DLOCKED_BOX.RowPitch` 与 `SlicePitch`，但调用方按字节步长写入。这会让行、层数据相互覆盖，影响三维颜色校正查色表。补丁现在返回字节步长，上传时使用相应行长和层偏移，并用 `delete[]` 释放数组。

传给 Host 的四个 32 位字段仍是：每块字节数、每行块数、每层块行数、深度。不能直接把修正后的字节步长传入这些字段，否则 Host 会再次乘以每块字节数。普通纹理和块压缩纹理均按原协议上传。

## 构建与游戏复测

1. 将修复提交到仓库后，在 Actions 的 `Build latest upstream Bridge` 中启用 `force_rebuild`。仅修改本仓库补丁而上游提交不变时，默认检查可能跳过已发布版本。
2. 等待 x86 客户端、x64 Host 编译及诊断测试完成。退出游戏并备份原安装，安装新构建的完整包。
3. 在此前出现偏色的服务器和地图，固定位置、视角、画质、Mod、后端及驱动，分别截图比较旧桥接、新桥接与无桥基线。
4. 检查场景色调、颜色校正切换和贴图，连续换图至少三次，再正常退出。保存两侧桥接日志；记录地图、显卡、驱动、后端版本和构建提交。
5. 如果仍有偏色，保留对比截图和日志继续定位。PR 作者的成功实测不能替代本 Nightly、后端变体及用户设备的复测。
